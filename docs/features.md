# 这个插件实际会做什么

不用记包名。日常用下来，你接触到的主要是几件事：记忆、skill 的写入和整理、偶尔出现的复盘、技能多时的检索，以及写入前的确认和事后的回退。它们不是一个固定流程，触发条件也不一样。

## 记忆

新会话刚开始，Agent 可能已经知道这个项目的构建命令、目录约定，或者你之前反复解释过的偏好。这些内容来自 `$DSH_HOME/memories/MEMORY.md` 和 `USER.md`。你可以直接让它“记住……”，它自己觉得某条事实值得留下时也会写。

记忆有硬上限：项目记忆默认 2200 字符，用户画像 1375 字符。写满之后，新内容会被拒绝；它得先删掉、压缩或合并旧内容，才能继续写。它不会悄悄截断，也不会自动扩容。

## skill

Agent 可以把一套重复做法写成 skill，比如“发布前要跑哪些检查”“这个项目的调试步骤”。创建、修补、拆分、归档都走 `skill_manage`。技能会进入平台的技能目录，模型之后可以按名称和简介发现它。改坏了可以用 `/evolution skill history <name>` 看版本，用 `/evolution skill undo <name>` 退回。删除是归档，不是硬删。

技能多起来以后，默认的完整目录会变得不划算。这时可以用 `skill_search` 找相关技能；如果装了 discovery 并打开它，还可以用域卡和目录裁剪，让模型一次不必看到全部技能。后者默认关闭，需要模型和投影条件，不是每个安装形态都能直接开。它解决的是“技能太多怎么找”，不保证模型每次都会选对。

## 复盘

一段任务收尾时，Agent 可能回头看一眼刚才的过程，给出“下次应该怎么改”的建议。默认累计约 10 次工具调用后触发，不是每句话都跑。它会让模型多跑一轮，所以你会看到一条额外的自我复查消息。

频率可以调，也可以关掉。它和 skill 写入不是一回事：复盘负责观察和提议，真正写不写、怎么写，还是走写入路径。

## 整理

技能放久了会过时，也会有重复。整理器会按时间和空闲条件把过时技能标成 stale、归档，把近重复的合并。宿主启动约 10 秒后判断一次，之后每小时查一次；距上次整理满 168 小时、你又空闲约 2 小时，才会真正跑。

它先做快照。失败时只写报告，不会自动把整棵技能树回滚。删除是归档，不会硬删。整理完不一定会在对话里提醒你，技能也可能直接从列表里消失；要看它做了什么，用 `/evolution curator status` 和 `/evolution curator report`。

## 合并

两个 skill 高度重叠时，可以合并成一个。默认 `mergeApproval=false`，合并会自动接受并写入；想每次人工确认，就打开审批。合并需要本地筛选模型，没有配置时会明确报错，不会自动下载。

合并是独立流程，有自己的候选筛选、提交和回执，不走普通写入审批。面板只读，负责展示队列和复制命令；合并结果可以撤销。

## 用户能控制什么

审批默认关闭。打开后，只有可暂存的 memory/skill 写入会停下来等你批准；整理器的归档/合并、合并器的提交不经过它。待批主要在有设置页的安装形态里看得到，通知和收件箱还不完整。

这套设计的出发点，是在“模型自动做语义判断”和“用户精力有限”之间找平衡：低风险、可回退的动作自动做，关键写入让人确认，技能写入留版本，删除归档，单技能能撤销，整树能恢复。当前实现没有把这件事做满，审批覆盖范围和通知都还有缺口。

| 能力 | 默认 | 什么时候需要管 |
|---|---|---|
| 审批 | 关闭 | 不放心自动写时打开 |
| 技能健康面板 | 完整体验里默认关闭 | 需要看结构体检时；普通使用可以不碰 |
| 合并 | 需要本地合并模型；默认自动接受 | 想每次人工审批时打开 `mergeApproval` |
| 模型/API key | 自动复盘、LLM 整理、域生成需要 | 见 [API key 与模型](api-keys.md) |

## 界面

设置里的「自进化」只有 `all` + Web/桌面 GUI 才有。里面有：

- 待批写入：审批开启时，批准/拒绝的入口；
- 诊断：和 `/evolution doctor` 同一份检查结果；
- 参数卡：记忆、复盘、整理、合并等常用项。

左侧栏也是只有完整安装才有：

- 技能历史：版本、差异、正文、撤销；
- 技能合并：待判断/待批准/待合并/无需合并四个队列，只读；
- 技能健康：结构体检，默认关闭。

host、preset、分层都不带这些面板。

## 它不做什么

不训练模型，也不把对话上传到托管服务。

host 形态没有记忆/技能写入工具，这是缩配，不是 bug。

它不替你做策略或审批决定。它也不保证模型每次都能选对 skill；描述、触发条件和任务本身都会影响选择。健康、漂移、图这些检查只报告，不会自动修复。
