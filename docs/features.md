# 功能指南

dsh-evolution 将项目事实写入记忆，将可复用流程保存为技能，并提供复盘、整理、合并、审批和诊断。各项能力有不同的触发条件；安装形态和模型配置会改变可用范围。

## 记忆

记忆分为项目记忆 `MEMORY.md` 和用户画像 `USER.md`，默认存放在 `$DSH_HOME/memories/`。可以明确要求 Agent 记住一条事实，Agent 也可以通过 `memory` 工具主动保存稳定的环境信息、偏好和工作约定。

新会话通过快照获得记忆内容。注入有边界：威胁扫描命中的条目会被过滤，异常超大的文件会跳过，因此“全量注入”不等于每条落盘内容都必然进入模型上下文。

默认字符预算为项目记忆 2200、用户画像 1375。写入后的结果超过预算时，本批写入被拒绝，不会静默截断；可以在同一批操作中删除或压缩旧条目后再写入。调低预算后，如果已有单条内容超过新上限，替换可能先被超限保护拒绝，此时应先删除或缩减该条目。预算可在设置中调整。

`host` 形态不提供 `memory` 工具。需要模型直接读写记忆时，使用 `all`、`preset` 或分层 Evolution 预设。

## 技能发现、使用与更新

### 技能写入与目录

Agent 通过 `skill_manage` 创建、修改、归档技能，也可以移动章节到支撑文件、提取内容到已有技能。写入经过参数检查、策略保护、读取前校验等门禁；创建和裸删除另有独立的前台确认设置。

技能进入技能目录后，目录提供者把符合发布条件的技能名称、简介和调用信息交给平台。默认发布全部可见且符合条件的条目，模型通过原生 `skill` 工具按名称加载正文。目录可见不等于模型必然选择或正确执行某个技能。

`skill_search` 是独立的本地检索工具，按查询返回候选，正文仍需另行加载。它不依赖 discovery 的域卡，也不需要 API key。

discovery 的域卡和目录裁剪默认关闭（`mode: off`）。开启 `mode: on` 后，初始域生成需要可用的模型提供方；投影还需要检索和会话投影条件。投影不可用时会保留完整目录，不能把裁剪后的结果当作完整的技能清单。

### 使用后的更新

复盘提示词要求模型先检查本次会话加载或读取过的技能，优先修补已经覆盖该任务的技能，再考虑已有伞技能，最后才创建新技能。这是模型遵循的写入策略，不是对每次复盘结果的硬保证。

直接写入并不都受“必须先读”限制：前台写入豁免 read-before-write，部分无法取得会话读取证据的路径会降级放行。需要核对实际写入时，应查看技能历史和变更记录，而不能只看复盘结论。

技能删除采用归档，单个归档技能可用 `/evolution skill restore <name>` 恢复。技能历史记录内容版本，但历史写入是 best-effort：历史记录失败不会使已经完成的技能写入失败，因此不能把每次写入都视为必然可撤销。

## 复盘

默认复盘模式为 `inject`，在当前会话追加一次模型回合。累计达到阈值的复盘不会在任务中段执行，而是保留到完成边界再投递，因此会产生额外的模型调用和上下文成本。

`cadence` 通道只统计具有实质信号的回合。满足以下任一条件即可计入：本回合至少 3 次工具调用、用户文本至少 200 字符、助手文本至少 500 字符。

记忆和技能各有默认间隔 10，但计数不是简单的工具调用总数：

- 回合带有对应领域的信号时，该领域计数加 1；
- 没有对应信号时，该领域计数加 `max(1, 本回合工具调用数)`；
- 达到间隔后记录待复盘类型，并在完成边界合并投递。

`skillReviewTrigger` 默认是 `cadence`。改为 `completion` 或 `both` 后，长会话完成通道还会使用默认 20 次累计工具调用的门槛。完成通道累计所有完成回合的原生工具调用数，不要求单轮满足上述实质信号；同一完成边界不会重复投递两条复盘。

`branch` 模式改为创建子会话，并把当前会话事件作为种子。它用于需要独立审查和计划记录的路径，不代表默认模式。

## Curator：生命周期整理

curator 负责技能库的生命周期整理。默认在宿主启动约 10 秒后进行首次到期判断，之后每小时判断一次；距上次整理达到 168 小时且近期会话空闲达到 2 小时，才执行自动整理。

默认生命周期阈值为 30 天标记 stale、90 天归档。实际候选还受创建时间、使用记录、固定标记、保护名单和引用关系限制。整理前会建立快照，删除采用归档，结果通过 `/evolution curator status` 和 `/evolution curator report` 查看。

默认 `llmReview=false`，curator 不运行 LLM 提名通道，因而不执行由该通道产生的近重复合并。需要独立事务、暂存树和回执的技能合并，使用下面的 merge 流程。

## Merge：显式技能合并

merge 不进行默认后台扫描。通过 `/evolution merge scan` 扫描候选，或用 `/evolution merge pair <a> <b>` 明确指定两个技能，才会启动合并流程。

scan 的候选筛选需要 `mergeModelsRoot` 下的本地 potion 模型文件：

- `potion-multilingual-128M-int8/`
- `potion-multilingual-128M-pca64-int8/`

这些文件不会自动下载。scan 的引擎判断可以使用当前模型；没有可用的模型服务时回退到 stub 判断，但本地筛选模型仍是扫描的必要条件。

普通 pair 直接提供技能对，不执行上述本地候选筛选，也不要求 potion 目录。它的 round1 和后续 authoring 使用子会话模型，因此仍需要可用的模型与子会话通道，没有 scan 的 stub 降级路径。

`mergeApproval=false` 是默认值：通过合并判断后自动进入 approved 并继续暂存和提交。设为 `true` 后，记录在 pending 状态等待 `/evolution merge approve <id>` 或 `reject <id>`。该开关独立于普通写入审批。

`/evolution merge pair --force` 是已注册的强制路径，但当前默认 `mergeApproval=false` 时，forced decision 不会建立 round1 子会话，后续 round2 会以 `no-session` 失败。不要把它作为普通 pair 的可用替代。

提交使用独立事务并保留回执。可用 `/evolution merge status <runId>` 查看运行，用 `/evolution merge undo <target> --run <id>` 按运行撤销目标合并。

## 模型调用的数据边界

记忆、技能、报告和运行状态等插件数据默认写入 `$DSH_HOME`。本地落盘不等于内容不会离开机器：

- 默认复盘使用当前会话模型，模型提供方会处理会话上下文和复盘提示词；
- `branch` 复盘会把当前会话事件复制为子会话种子；
- curator 的 LLM 提名会向所配置模型发送候选技能和整理提示词；
- discovery 域生成会发送技能名称、简介和触发信息；
- merge scan 的引擎判断会使用当前模型，未启用该通道时才使用 stub；普通 pair 的 round1/authoring 使用子会话模型。

使用外部模型提供方时，相应内容会发送到该提供方。各功能在无模型时的失败、跳过或降级行为见 [API key 与模型](api-keys.md)。

## 审批与恢复

普通审批默认关闭。开启后，它只拦截可暂存的 memory/skill 写入，包括相应的 graph 写入路径；它不覆盖 curator 自己的归档或整理写入，也不代替 merge 的 `mergeApproval`。

常用命令为 `/evolution pending`、`/evolution approve <id>` 和 `/evolution reject <id>`。待批记录默认不过期；配置非零保留时间后，超时记录按拒绝处理，不会执行。

技能创建和裸删除的前台确认由 `skillWriteConfirm` 独立控制，默认 `auto`，与普通审批不是同一道门。

恢复入口按作用域区分：

- 单个归档技能：`/evolution skill restore <name>`；
- 技能正文版本：`/evolution skill history <name>` 与 `/evolution skill undo <name>`；undo 不恢复支撑文件，支撑文件版本需另查历史；
- 整棵技能树：`/evolution restore`，使用最近的快照；
- 一次合并：`/evolution merge undo <target> --run <id>`。

撤销能力依赖实际存在的历史、快照或合并回执；history 的 best-effort 写入边界仍然适用。

## 诊断、反馈与界面

### 诊断与健康

`/evolution doctor` 检查安装形态、版本、冲突、连接和服务状态。它不能替代一次真实的记忆写入或技能修改，也不能仅凭服务已挂载证明模型工具在目标会话可用。

技能健康、漂移和维护报告用于观察结构与引用问题。报告本身不执行修复，修复仍需明确的写入、整理或合并动作。

### 反馈与 replay

反馈模块可以保存评分并生成反馈分数，但家族当前没有内置的反馈生产者。外部宿主必须显式调用 `record(target, rating, ...)` 接入反馈；已有命令或文本不会自动转换成技能评分。

`/evolution replay` 对已记录的计划结果进行评分和比较，不重新运行计划。它消费 `evolution/plan-applied` 事件及 activity 历史。默认 `inject` 复盘不发出该事件，因此默认模式不会产生新的 replay 数据；没有既有 branch 计划记录时，没有可比较的计划。

### 图形界面

`all` 安装形态在 Web/桌面 GUI 提供“自进化”设置区、技能历史面板和技能合并面板。设置区包含待批写入、诊断和常用参数；合并面板只读，动作通过复制命令完成。

技能健康面板随完整包提供但默认禁用。`host`、`preset` 和分层预设不包含这些 Web 设置与侧栏面板。
