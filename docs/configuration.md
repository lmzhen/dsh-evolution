# 设置

默认值基本能用。需要动的通常只有审批、记忆预算、复盘、整理这几类。检索和合并是条件功能，不用可以完全不管。

## 审批

默认关闭。打开后，只有可暂存的记忆/技能写入会停下来等你批准；整理器的归档/合并、合并器的提交不走这里。

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用审批 | 否 | 打开后写入需要 approve/reject |
| 批准时再确认 | 自动 | `auto` 直接执行；`ask` 再问一次 |
| 待批保留时间 | 永久 | 过期会按拒绝处理，一般不用改 |

设置页在「自进化」里的审批区。只有 `all` + Web 客户端才有这个页面；host、preset、分层没有，得用命令或改 profile 配置。

## 写入确认

这是另一条路径，管的是“创建/删除技能前先问一句”，和审批不是一回事。

| 设置 | 默认 | 说明 |
|---|---|---|
| `skillWriteConfirm` | `auto` | 新建/裸删技能前是否问；`ask` 会等，`timeout` 超时后取消 |
| 确认超时 | 120 秒 | 仅 `timeout` 模式使用 |

审批管的是写入排队；这个确认管的是动作前的一次询问。可以只开一个。

## 记忆预算

| 设置 | 默认 | 说明 |
|---|---:|---|
| `memoryChars` | 2200 | 项目记忆 `MEMORY.md` 的字符预算 |
| `userChars` | 1375 | 用户画像 `USER.md` 的字符预算 |

写满后，新增会被拒绝；删除、替换仍然可以。用到 80% 左右开始出现存储提示。把预算改小不会立刻删内容，下一次写入时才按新预算判断。

## 复盘

| 设置 | 默认 | 说明 |
|---|---|---|
| `reviewEnabled` | 是 | 总开关 |
| `reviewMode` | `inject` | 在会话内复盘；`branch` 另起子会话 |
| `reviewMemoryInterval` | 10 | 累计多少次工具调用触发记忆复盘 |
| `reviewSkillInterval` | 10 | 累计多少次工具调用触发技能复盘 |
| `skillReviewTrigger` | `cadence` | 只按节奏、只按完成，或两者；完成阈值默认 20 |

`inject` 是默认路径，在任务收尾时触发，会让模型多跑一轮。`branch` 需要额外支持，当前还有通知边界。不想被打扰就调大间隔，或者直接关掉。

## 整理

| 设置 | 默认 | 说明 |
|---|---|---|
| `curatorIntervalHours` | 168 | 自动整理间隔（小时） |
| `staleAfterDays` | 30 | 多久不用算 stale |
| `archiveAfterDays` | 90 | 多久不用归档 |
| `minIdleHours` | 2 | 你空闲多久后才自动整理 |

整理先快照。失败只写报告，不会自动回滚整棵树；需要时用 `/evolution restore`。归档不是硬删除。整理完成后不一定有对话通知，技能也可能直接从列表消失。

## 技能多了以后的检索

`skill_search` 本身是独立可用的基础检索。这里默认关闭的是 discovery 的域卡和目录裁剪：它适合技能数量增长、完整目录不再合适时使用，需要模型/投影条件，并由支持人员开启。除非确实需要，否则不用开。

## 合并

合并需要本地筛选模型。没有配置时，`/evolution merge doctor` 会提示，`merge scan` 会失败；不会自动下载，也不会假装成功。

不用合并就不用管这一节。默认 `mergeApproval=false`，合并会自动接受并写入；想每次人工确认就打开它。合并是独立流程，不走普通写入审批。

## 在哪里改

设置里的「自进化」放常用项：审批、记忆、复盘、整理。

也可以用 `/evolution params --group <group>` 看当前值和来源，常用组是 `review`、`memory`、`curator`、`merge`。

设置页写入的就是 profile 的 `cordis.patch.yml`。不要一边用页面改、一边手改同一个文件，容易互相覆盖。以 `doctor` 或 `params` 显示的实际值为准。
