# dsh-evolution

## 这个插件是用来做什么的？

本插件以 skill 的自动化生成和全生命周期管理为主要目标，服务于个性化能力沉淀。它是一个面向任务的插件：让模型在真实工作中逐步形成并维护适合用户环境、偏好和流程的专用技能，从而提高对这些任务的适配程度。

这里的全生命周期包括技能的创建、发现、使用、复盘修补、结构调整、合并、归档与恢复。这些能力按需组合，不要求每个技能都经过同一条固定流程。插件还提供有预算限制的记忆模块，用来保存跨会话的项目事实和用户偏好。

插件不改变模型本身，也不提供托管模型服务。需要语义判断的工作由 DSH 已配置的模型完成；写入、整理和恢复则受当前代码中的门禁、快照、历史与审批机制约束。

## 什么是 skill？

早期的大模型以自回归方式生成文本。问题、指令与回复之间存在统计关联，因此，越能准确描述领域、任务和约束的提示词，通常越有助于得到符合要求的答案。这构成了早期提示词工程的重要基础。

思维链和模型能力的提升，减少了一部分单步任务对面面俱到的提示词的依赖：模型可以在推理过程中调用已有的术语和规范。但工具调用时代的工作目标发生了变化，模型不只生成一段内容，还要完成一串操作。此时，执行顺序、工具约束、完成标准和失败恢复仍然需要明确说明。提示词由对单次回答的描述，逐步扩展为可执行流程的操作手册。

不同任务需要不同手册，不可能全部长期放进上下文。一种做法是把各步骤的提示词与输入输出连接成固定工作流；另一种做法是在模型能够按名称和简介选择能力之后，把操作手册封装为按需加载的模块。后一种模块就是 skill。在 DSH 中，一个 skill 通常由 `SKILL.md` 正文和可选的脚本、模板、参考资料等支撑文件组成。模型按名称和简介发现 skill，再通过原生 `skill` 工具按需加载。

skill 与 MCP 不属于同一层。MCP 是工具与资源的连接协议；skill 描述在特定任务中何时使用哪些能力、按什么顺序执行，以及做到什么程度算完成。把二者混为一谈，会看不清本插件管理的是流程知识，而不是工具连接本身。

## 开发本插件的目的是什么？

模型能力的发展带来了两个相互关联的变化：

1. **部分通用 skill 的边际价值下降。** 一些公开、通用且常见的操作方法，正在通过训练成为模型能力的一部分。对于这类任务，单独维护一份通用操作手册的收益会减少，但这并不意味着所有通用 skill 都失去作用。
2. **模型开始具备从执行轨迹中整理操作方法的能力。** 在轨迹真实、反馈明确的情况下，模型可以把一次任务的步骤、约束和修正过程整理成可复用的 skill。当前插件正是利用这一能力进行复盘和技能写入；生成结果仍需经过结构检查，必要时还需要人工审批，不能把模型输出视为天然正确。

与此同时，每个用户的设备环境、项目约定、个人偏好和复杂任务细节仍然不同。通用能力过关之后，真正影响任务完成质量的，往往是只对某个人或某个项目成立的流程知识。专用 skill 会随着任务种类和复杂度增长而增加，也会出现重复、过时和结构调整的需求，完全依赖人工维护并不可取。

因此，本插件希望利用模型的语义能力，自动完成适合自动化的生成与维护工作，同时保留人工控制和回退手段。它追求的不是无约束地扩充技能数量，而是在真实任务中形成可用、可检查、可维护的专有技能集合。

## 与通常的记忆插件相比，本插件的定位是什么？

二者总体上呈互补关系。通常意义上的记忆插件以事实为管理对象，例如用户是谁、项目是什么、曾经作出过什么决定；本插件更关注流程，即一类任务应当怎样完成、按什么顺序执行、达到什么标准。后者主要服务于需要通过 Harness 让模型持续完成实际工作的场景。

本插件也包含记忆模块，但设计取舍与常见的随取随用、持续增长的记忆系统不同：

- **记忆有硬字符预算。** 项目记忆 `MEMORY.md` 和用户画像 `USER.md` 的默认预算分别为 2200 和 1375 字符。写入后的结果超过预算时，本批写入会被拒绝，不会静默截断；模型需要先删除或压缩已有内容，再写入新内容。调低预算后，如果已有单条内容超过新上限，替换也可能被超限保护拒绝，此时删除是恢复通道。
- **记忆通过快照注入，而不是只在模型主动检索时提供。** 这样设计是为了让关键项目事实在任务中保持可见，避免重要信息仅因模型没有发起检索而被遗漏。

快照注入并不等于每条落盘内容都百分之百进入模型上下文：威胁扫描命中的条目会被过滤，异常超大的文件会被跳过。字符预算限制的是注入规模，不能进一步推出所有任务都没有性能损失或额外上下文成本。它表达的是一种明确的工程取舍：在有限上下文内优先保留关键事实，同时把流程知识交给可维护的 skill。

## 本插件提供了哪些能力？

以下能力都已有对应的代码入口。它们的触发条件不同，不能理解为每项任务都会经过全部环节。

| 功能 | 当前行为与默认条件 |
|---|---|
| 技能生成与更新 | Agent 可通过 `skill_manage` 创建和修补技能。默认复盘按 10 次加权工具调用的间隔，在满足 cadence 实质信号后的完成边界提示模型生成或更新技能，不保证每次复盘都产生新技能 |
| 技能目录与检索 | 默认发布完整技能目录，模型通过原生 `skill` 工具加载；`skill_search` 提供本地检索，discovery 的域卡和目录裁剪默认关闭 |
| 技能库整理 | curator 默认按时间间隔和空闲条件执行确定性整理，标记过时技能并归档；LLM 合并提名需单独启用 |
| 技能合并 | 通过 `/evolution merge scan` 或 `pair` 发起。scan 需要本地 potion 模型，缺少 LLM 时可回退 stub；普通 pair 不需要 potion，但 round1/authoring 需要子会话模型。发起后默认自动批准，`mergeApproval` 可改为人工批准 |
| 记忆 | `all`、`preset` 及分层预设的选定会话提供。项目记忆和用户画像预算分别为 2200、1375 字符；达到上限后拒绝新增，不静默截断 |
| 写入审批与恢复 | 普通写入审批默认关闭，开启后可暂存记忆和技能写入；curator 与 merge 使用各自控制。技能历史、正文撤销、单元撤销和归档恢复的适用范围不同，执行期失败不承诺都能完整回退 |
| 诊断与界面 | 提供 `/evolution doctor`、整理报告、技能健康和知识图；`all` 在 Web/桌面 GUI 提供进化工作台（技能历史/待批/合并/健康）和诊断卡，健康视图默认关闭 |

各项功能的触发条件、失败行为和限制见 [功能说明](docs/features.md)。

## 安装

环境要求、四种安装形态和升级步骤见 [INSTALL.md](INSTALL.md)。默认安装完整形态：

```bash
dsh plugin --profile web add @lmzhen/dsh-evolution-all
# 重启 DSH，然后在会话中执行：
/evolution doctor
```

桌面 GUI 将 `--profile web` 改为 `--profile desktop`。安装后可让 Agent 记住一条项目事实，再开新会话确认记忆已注入；`doctor` 用于检查安装形态和服务状态，不能替代实际读写验证。

完整源码布局的安装结果为 35 个包；发布清单共 36 个包，agent preset 单独计算。

## 安装形态

| 形态 | 适用场景 | 能力与界面 |
|---|---|---|
| `all` | 默认完整使用 | 所有会话提供记忆和技能工具；Web/桌面 GUI 提供进化工作台与诊断卡 |
| `host` | 不授予模型记忆/技能写入工具 | 保留显式合并、后台整理、手动维护和诊断；自动复盘与用量统计不生效，无进化工作台和诊断卡 |
| `preset` | 旧配置迁移 | 工具范围接近 `all`，但无设置页和侧栏面板 |
| 分层预设 | 仅在选定会话提供工具 | `host` 加 Evolution 预设；其他会话不启用插件的自动行为，无设置页和侧栏面板 |

同一 profile 只能使用一种形态。精确的会话影响见 [packages/INSTALL.md](packages/INSTALL.md)，安装命令见 [INSTALL.md](INSTALL.md)。

## 常用命令

| 命令 | 用途 |
|---|---|
| `/evolution doctor` | 检查安装形态、版本和服务状态 |
| `/evolution pending` | 查看等待审批的普通写入 |
| `/evolution skill history <name>` | 查看技能正文和支撑文件的历史 |
| `/evolution skill undo <name>` | 回退技能正文；不恢复支撑文件 |
| `/evolution curator status` | 查看自动整理状态 |
| `/evolution merge status <runId>` | 查看已发起的合并运行 |
| `/graph` | 浏览或编辑技能与记忆图 |

完整命令说明见 [docs/commands.md](docs/commands.md)，常用配置见 [docs/configuration.md](docs/configuration.md)。

## 数据与安全

- 默认装配的插件数据保存在 `$DSH_HOME`，不依赖家族托管服务。备份与恢复范围见 [运维指南](docs/operations.md)。
- 受控的记忆/技能模型写工具会扫描调用参数，相应写路径执行结构检查和策略保护；审批是可选的附加控制，不替代这些检查，也不覆盖整理器和 merge 的内部写入。
- 技能删除采用归档。正文历史记录失败不会阻断原写入，因此撤销前应确认可用版本；支撑文件不随正文撤销回退。整理前快照可恢复，合并保留运行记录和撤销依据。
- 本地保存不等于内容不外发：复盘、LLM 整理和 discovery 域生成会把相应任务或技能内容发送给所配置的模型提供方；branch 复盘还会向子会话复制会话事件。
- API key 由 DSH 的模型与凭据配置管理，不应写入技能、记忆或插件配置。详见 [模型与 API key](docs/api-keys.md)。
